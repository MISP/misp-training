\section{Client, models and API}

\begin{frame}{Pin the client and identify the server}
\begin{itemize}
\item Reviewed: MISP 2.5.50 and PyMISP 2.5.34.4.
\item PyMISP requires Python 3.10 or later, below 4.0.
\item PyPI and GitHub release checked on 2 November 2026.
\item Server and client version numbers need not match.
\end{itemize}
\note{The installed release is 2.5.34.4, checked against PyPI metadata and the GitHub release. Its source revision is 45c906070c287dffeed353069cb3daddceab2ea3; MISP 2.5.50 is fc99c9e3fc85beddc6ef18835359f3c8b7f44608. This course uses Python 3.12. Consult the server's getVersion response and pymisp\_recommended\_version; current package does not imply every server supports every operation. Recheck releases before refreshing the pin.}
\end{frame}

\begin{frame}{Two complementary interfaces}
\begin{itemize}
\item \code{PyMISP}: authenticated requests to the server.
\item \code{MISPEvent}, \code{MISPAttribute}, \code{MISPObject}: local models.
\item Model changes and JSON conversion do not save remotely.
\item Use the public client methods to persist intended changes.
\end{itemize}
\note{The PyMISP constructor itself performs server requests for version, current-user/role/settings and attribute types. Do not put it in an offline cell. Creating a MISPEvent and adding attributes/objects are local operations. ExpandedPyMISP remains a compatibility class in this release; use PyMISP for new examples. Model helpers simplify encoding but do not bypass server validation or access control.}
\end{frame}

\begin{frame}{The Python methods still use REST routes}
\small
\begin{tabular}{@{}ll@{}}
\toprule
Python operation & REST route in this snapshot \\
\midrule
\code{search_index(...)} & \code{POST events/index} \\
\code{search(...)} (attributes) & \code{POST attributes/restSearch} \\
\code{get_event(uuid)} & \code{GET events/view/{uuid}} \\
\code{add_event(event)} & \code{POST events/add} \\
\code{update_attribute(...)} & \code{POST attributes/edit/{uuid}} \\
\bottomrule
\end{tabular}
\note{The table shows the ordinary calls used here. get\_event can use POST when passing certain options. Additional methods map to objects/add, tags/attachTagToObject, sightings/add and events/delete. An HTTP POST is not necessarily a write: restSearch is a read operation. See the REST API course for raw request/response envelopes and the deployed instance's api/openapi and api/rest interfaces.}
\end{frame}

\begin{frame}{Authentication and visibility remain server decisions}
\begin{itemize}
\item The raw auth key goes in the Authorization header.
\item An API-enabled role and visible data are still required.
\item Advanced keys can restrict IPs, expiry and read-only use.
\item Read-only keys can POST searches; they cannot create events.
\end{itemize}
\note{Obtain a permitted auth key through your own instance's profile/auth-key interface, rather than a hard-coded community host. Keys inherit account visibility and relevant role permissions, with additional advanced-key restrictions. A writer can get proposals instead of edits on records it does not own. Never use a site-admin result as evidence of ordinary-user visibility. The lab uses an ordinary writer and a read-only key; administrative provisioning is separate from learner exercises.}
\end{frame}

\begin{lstlisting}

python -m pip install -r examples/requirements.txt

\note{Run from a.2-pymisp. requirements.txt pins pymisp==2.5.34.4. The package's dependencies are resolved by pip; this is a course-version pin, not a complete transitive lockfile. Use python -m pip install --upgrade pymisp to assess a future release in a separate environment, then rerun checks and update the pin deliberately. File-analysis extras are optional and are not required for the synthetic domain-ip exercise. Avoid sudo pip and unpinned Git main installs as the classroom baseline.}
\end{frame}

\begin{frame}[fragile]{Connect with trusted TLS and bounded request timeouts}
\begin{lstlisting}[language=Python]
from pymisp import PyMISP
from examples.common import Config

config = Config.from_env()
misp = PyMISP(config.url, config.key,
              ssl=config.verify, timeout=(5, 60),
              debug=False)
\end{lstlisting}
\note{Set MISP\_URL and MISP\_API\_KEY outside committed code and notebooks. Config preserves a trailing slash, including a deployment subdirectory: this release's search uses urljoin. For a private CA, REQUESTS\_CA\_BUNDLE supplies a trusted CA bundle to ssl; otherwise verification remains True. HTTP is allowed only on loopback for an isolated disposable lab. Timeout is a connect/read tuple, not an overall workflow deadline. Requests retains normal environment proxy handling. Do not print the client or key.}
\end{frame}

\begin{frame}[fragile]{Check the response before using it}
\begin{lstlisting}[language=Python]
from pymisp import MISPEvent
from examples.common import expect_model

saved = expect_model(
    misp.get_event(event_uuid, pythonify=True),
    MISPEvent,
)
\end{lstlisting}
\note{PyMISP can raise transport/server/decoding exceptions or return an errors dictionary. pythonify=True does not guarantee a typed success. Bulk attribute addition has its own attributes/errors result shape, and some denied single-attribute writes can fall back to proposals. The helpers check expected model types and action results, then the workshop refetches saved state. An empty list from a valid search is different from an error. Avoid printing full responses or verbose logs into shared notebooks.}
\end{frame}

\section{Read the right data}

\begin{frame}{Choose the search scope first}
\begin{itemize}
\item \code{search_index}: event summaries from the index.
\item \code{search(controller="events")}: matching events.
\item \code{search(controller="attributes")}: matching attribute rows.
\item \code{get_event(uuid)}: one known event and its context.
\end{itemize}
\note{search defaults to the events controller. This released generic search method accepts events, attributes and objects; other endpoint families have dedicated methods. metadata=True on event search omits attributes and proposals; it is not the same as a full event with no attributes. Choose the controller to match the unit being consumed. Event and attribute limits count different things.}
\end{frame}

\begin{frame}[fragile]{One typed attribute page}
\begin{lstlisting}[language=Python]
rows = misp.search(
    controller="attributes", return_format="json",
    type_attribute="domain", value="%.example",
    include_event_uuid=True, include_event_tags=True,
    order="Attribute.id ASC", limit=10, page=1,
    pythonify=True,
)
\end{lstlisting}
\note{Use one\_page from examples/read.py for the checked version. These are reserved synthetic .example domains. published and to\_ids are deliberately omitted so ordinary JSON includes both states in the reviewed source. Attribute results can include attributes contained in objects. The code retrieves one page, not a complete export, and prints UUIDs/types rather than arbitrary incident values.}
\end{frame}

\begin{frame}{Raw JSON, normalised JSON and typed models differ}
\small
\begin{tabular}{@{}ll@{}}
\toprule
Interface & Attribute-search result \\
\midrule
Raw HTTP JSON & \code{response.Attribute} array \\
PyMISP JSON & Dictionary containing \code{Attribute} \\
PyMISP with \code{pythonify=True} & List of \code{MISPAttribute} objects \\
\bottomrule
\end{tabular}
\medskip
\normalsize Do not reuse the raw-envelope parser on typed results.
\note{PyMISP's response checker unwraps the outer response field. Event searches have a different normalised shape. The notebook sends the equivalent bounded raw query and compares UUID sets with typed output on a stable fixture. pythonify=False does not restore the raw HTTP envelope. Large pythonified results use memory; retrieve bounded pages and retain only needed fields.}
\end{frame}

\begin{frame}{Translate parameter names and states deliberately}
\small
\begin{tabular}{@{}ll@{}}
\toprule
REST JSON & PyMISP keyword \\
\midrule
\code{type} & \code{type_attribute} \\
\code{returnFormat} & \code{return_format} \\
\code{includeEventUuid} & \code{include_event_uuid} \\
\code{includeEventTags} & \code{include_event_tags} \\
\code{enforceWarninglist} & \code{enforce_warninglist} \\
\bottomrule
\end{tabular}
\note{Use numeric 0/1 when restricting published or to\_ids in these search examples; avoid assuming Python False or literal JSON false consistently selects state 0 on every endpoint. This PyMISP release rejects to\_ids=[0,1], although the raw endpoint supports that array. Omit to\_ids for both states in this ordinary JSON query. Unknown kwargs are forwarded, not necessarily validated: a misspelling may silently fail to constrain a query. The released-client contract tests exercise these translations.}
\end{frame}

\begin{frame}{A matching event can contain nonmatching attributes}
\begin{itemize}
\item Event search selects events using the supplied filters.
\item A full event result can include broader incident context.
\item Attribute search selects the rows required by a consumer.
\item Retain event UUID and inherited-tag context when needed.
\end{itemize}
\note{Searching events for type domain does not mean every attribute in each full returned event is a domain. The synthetic fixture contains a domain, an object domain and an IP. Compare event and attribute search results without flattening them into an assumed equivalent set. Inherited event tags are context; they do not establish a direct attachment to the attribute. A tag filter is not an access-control grant.}
\end{frame}

\begin{frame}{Traverse bounded pages without claiming false completion}
\begin{itemize}
\item Start at page 1 and use a stable order.
\item A role cap can make every nonempty page short.
\item For this ordinary JSON query, continue to an empty page.
\item Fail on repeated UUIDs or the maximum-page bound.
\end{itemize}
\note{collect\_pages is deliberately restricted to the fixed ordinary JSON/SQL-filtered query in examples/read.py. It returns only after an empty page, and raises rather than returning a silently truncated result on repetition or the bound. It accumulates in memory only for this small workshop. It is not a generic exporter, streaming sync engine or database snapshot. Post-query warninglist/decay filters can create empty output pages before the end; do not add them to this loop unchanged.}
\end{frame}

\begin{frame}[fragile]{Keep polling clocks and checkpoints explicit}
\begin{lstlisting}[language=Python]
from time import time
upper = int(time())
lower = previous_checkpoint - overlap_seconds
# Use the same bounds for every page:
rows = misp.search(controller="attributes",
                   timestamp=[lower, upper],
                   limit=100, page=1, pythonify=True)
\end{lstlisting}
\note{This is an illustrative first page, not an executable sync client. Define previous\_checkpoint and the initial backfill policy first. Attribute timestamp is the change clock at attribute scope; event\_timestamp is the parent-event clock; publish\_timestamp/last concerns publication; first\_seen/last\_seen are observation times. The timestamp window is inclusive. Upsert by UUID, overlap deliberately and advance the checkpoint only after every page and downstream write succeeds. Deletions, access loss and event-only context changes need reconciliation; ordinary polling is not MISP server-to-server sync.}
\end{frame}

\begin{frame}{Export format is also a selection policy}
\begin{itemize}
\item Ordinary JSON can include unpublished contextual attributes.
\item Detection formats can default to published and to\_ids records.
\item Set publication, to\_ids and warninglist policy explicitly.
\item A text export is a string, not a list of typed attributes.
\end{itemize}
\note{Use pythonify=True with JSON in this course. Do not assume changing only return\_format preserves the selected records. For a deliberate detection exercise use return\_format="text", type\_attribute="domain", published=1, to\_ids=1, enforce\_warninglist=True and pythonify=False, with an approved tag policy. The private unpublished fixture should not produce matching default detection output. Warninglists can remove rows after pagination. Synthetic .example output is not a production blocklist.}
\end{frame}

\section{Build, save and verify}

\begin{frame}[fragile]{Build a private synthetic event offline}
\begin{lstlisting}[language=Python]
from pymisp import MISPEvent

event = MISPEvent()
event.info = "PyMISP 2.5 training / synthetic"
event.distribution = 0
event.threat_level_id = 4
event.analysis = 0
event.published = False
\end{lstlisting}
\note{Adapted from the MISPEvent cells in the upstream FullOverview and archived Introduction notebook. Explicit distribution 0 means your organisation only. Threat level 4 is Undefined; do not confuse that enumeration with analysis or distribution. Published False is a field on the new draft, not a request to publish it. examples/models.py adds a unique run token and makes no server request.}
\end{frame}

\begin{frame}[fragile]{Add a contextual attribute to the local model}
\begin{lstlisting}[language=Python]
attribute = event.add_attribute(
    "domain", "observer.example", to_ids=False,
    comment="Synthetic observation only.",
)
attribute.comment = "Reviewed synthetic observation."
print(attribute.uuid, attribute.type)
\end{lstlisting}
\note{Use reserved .example names and documentation IPs rather than copied malware indicators from older notebooks. to\_ids=False means this is contextual data, not a deployment-ready detection assertion. event.add\_attribute changes only the local event. misp.add\_attribute sends a server request to an existing event. Preserve the distinction between a model helper and a client method. UUIDs support identity; names and values alone do not.}
\end{frame}

\begin{frame}[fragile]{Group related observations in a template-backed object}
\begin{lstlisting}[language=Python]
from pymisp import MISPObject
obj = MISPObject("domain-ip", strict=True,
                 standalone=False)
obj.add_attribute("domain", value="host.example",
                  to_ids=False)
obj.add_attribute("ip", value="192.0.2.10",
                  to_ids=False)
event.add_object(obj)
\end{lstlisting}
\note{Adapted from the domain-ip example in FullOverview. The first argument to object.add\_attribute is an object relation, not an arbitrary attribute type. The installed PyMISP wheel bundles templates, which can differ from the server's template catalogue. Strict construction plus obj.to\_json(strict=True) checks local template requirements; it does not prove server acceptance or analytical truth. See the object-template course for identifiers, required/requiredOneOf fields and updates. Binary/file generators need optional extras; they are outside this workshop.}
\end{frame}

\begin{frame}[fragile]{Inspect JSON and round-trip the local model}
\begin{lstlisting}[language=Python]
encoded = event.to_json(indent=2)
restored = MISPEvent()
restored.load(encoded)
assert restored.uuid == event.uuid
print(len(restored.attributes), len(restored.objects))
\end{lstlisting}
\note{to\_json returns a JSON string; to\_dict returns a mapping whose values may still include model/date objects. Do not json.dumps a JSON string and accidentally double-encode it. PyMISP's client serialises models for API calls. Successful local round-trip preserves structure and identity but does not establish server validation, permissions or persistence. The offline tests check the actual reference target and strict object-template requirements as well.}
\end{frame}

\begin{frame}[fragile]{Persist once, then use the server response}
\begin{lstlisting}[language=Python]
from examples.common import expect_model

created = expect_model(
    misp.add_event(event, pythonify=True), MISPEvent)
verified = expect_model(
    misp.get_event(created.uuid, pythonify=True), MISPEvent)
\end{lstlisting}
\note{The workshop starts from a newly generated draft and only modifies its own confirmed fixture. The response supplies server identity and accepted values; refetch to verify the outcome. Local event.add\_object versus remote misp.add\_object are different operations, as are local attribute.add\_tag and remote misp.tag. Do not automatically retry an ambiguous POST: a timeout can occur after the event was created. Inspect the intended draft UUID before retrying. Publishing is a separate operation and is deliberately absent.}
\end{frame}

\begin{frame}[fragile]{Update a known attribute and verify its identity}
\begin{lstlisting}[language=Python]
from pymisp import MISPAttribute
attribute = verified.attributes[0]
attribute.comment = "Reviewed in the workshop."
updated = expect_model(
    misp.update_attribute(attribute, pythonify=True),
    MISPAttribute,
)
assert updated.uuid == attribute.uuid
\end{lstlisting}
\note{Refetch before editing and make the narrowest intended change. Do not replay an old full event dump as a routine update or reuse stale timestamps as if they were optimistic-concurrency locks. The released client serialises edited model fields and handles timestamps; still verify persisted values. update\_attribute can return a proposal for a non-owned event, so require MISPAttribute rather than assuming any response means the original attribute changed. Check the refetched comment and to\_ids state.}
\end{frame}

\begin{frame}[fragile]{Reference an attribute from an object}
\begin{lstlisting}[language=Python]
obj.add_reference(attribute.uuid, "related-to",
                  "Synthetic teaching relation.")
# Add this before saving the event in the workshop.
\end{lstlisting}
\begin{itemize}
\item Keep the referenced UUID and relationship meaning explicit.
\item A local reference is not a correlation or Galaxy attachment.
\end{itemize}
\note{The executable fixture creates the reference before add\_event and verifies it after refetching the saved event. standalone=False retains object references when embedding the object in a full event dump. Cross-event references and references to unseen records have further server constraints and are not exercised here. Do not equate structural validity with evidence that a relationship is true.}
\end{frame}

\begin{frame}[fragile]{Tag at the intended scope}
\begin{lstlisting}[language=Python]
from examples.common import expect_success

expect_success(misp.tag(created.uuid, "tlp:clear"))
expect_success(misp.tag(attribute.uuid, "tlp:clear",
                        local=True))
\end{lstlisting}
\note{These are remote operations. The operator must make tlp:clear available and the writer needs tagging permission. The first is an event tag; the second is a directly attached local attribute tag. Refetch and inspect the local flag rather than inferring scope from a rendered inherited tag. A handling tag is not a distribution setting or an access-control grant. This private training event remains organisation-only and unpublished regardless of its TLP tag. Tag creation permissions are separate from attachment permissions.}
\end{frame}

\begin{frame}{Sightings and proposals have distinct meanings}
\begin{itemize}
\item \code{MISPSighting} plus \code{add_sighting} records an observation.
\item Target the intended attribute UUID, not a broad shared value.
\item Proposal methods create suggested changes for review.
\item A returned proposal does not confirm an original was edited.
\end{itemize}
\note{The workshop submits type 0 with the explicit source Synthetic PyMISP training sighting to its own attribute. It is a teaching record, not an external sensor observation. Type 1 denotes false positives and type 2 expiration; select deliberately. Single-attribute add/update/delete methods in this release can fall back to proposal methods for specific permission-denied responses. Bulk-add results also need per-item inspection. Other capabilities include analyst notes, event reports and feeds; consult current methods rather than assuming retired discussion/template APIs remain available.}
\end{frame}

\begin{lstlisting}

\end{lstlisting}
\begin{itemize}
\item Create a private event, attributes, object and reference.
\item Edit, tag, add a sighting and refetch the result.

\begin{frame}{Handle failures and diagnostics without losing meaning}
\begin{itemize}
\item Separate transport failure, API error and valid empty result.
\item Check saved state before retrying an uncertain write.
\item Keep keys, private payloads and verbose logs out of notebooks.
\item Record versions, query policy and validation limits.
\end{itemize}
\note{PyMISP uses Python logging and can include server bodies or request data in diagnostics, especially in DEBUG mode. Do not enable debug=True or dump exceptions/responses into shared artifacts on sensitive systems. A timeout is not proof that a write failed, and a boolean success-looking field alone is not proof of the intended state. Use a deliberate retry/backoff policy for read operations and endpoint-specific idempotency/reconciliation for writes. The sample CLI gives concise errors; local protected diagnostics still need review.}
\end{frame}
